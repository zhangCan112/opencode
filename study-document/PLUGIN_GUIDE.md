# 插件系统

了解 OpenCode 插件的原理、能力及使用方法

---

了解插件
插件是一种可扩展模块，能够在 OpenCode 运行时注入自定义行为。它通过钩子机制监听或修改关键事件，而无需改动核心代码。你可以用插件添加新的认证方式、拦截工具调用或记录日志。

---

原理说明
OpenCode 在启动时读取配置中的插件列表，依次加载并初始化每个插件。每个插件返回一个钩子对象，这些钩子被注册到全局事件总线上。当特定事件发生时（如工具执行前、会话开始等），所有已注册的钩子会按顺序被调用，并可以修改传入的数据或执行副作用。

---

主要能力
插件可以实现以下功能：自定义身份验证（OAuth、API Key 等）、在工具执行前后修改参数或结果、监听会话、消息和工具事件、向用户展示额外的提示或错误、集成外部服务或日志系统。通过组合这些能力，你几乎可以定制 OpenCode 的任何交互细节。

---

如何安装
在项目根目录的 `opencode.json`（或全局 `~/.opencode/opencode.json`）中添加 `plugin` 字段，列出要加载的插件来源。支持的来源包括 npm 包（如 `my-plugin@1.0.0`）、本地文件路径（如 `./local.js`）和远程 URL（如 `https://example.com/plugin.js`）。写入后重启 OpenCode，插件会自动下载并初始化。

---

如何开发
创建一个 TypeScript 或 JavaScript 文件，导出一个异步函数，函数接收 `PluginInput` 参数并返回 `Hooks` 对象。在返回的对象中，根据需要填充 `auth`、`event` 或特定工具名的钩子。例如，想在每次 bash 工具执行前打印日志，可在 `event.tool.execute.before` 中添加日志逻辑。完成后将文件路径加入 `opencode.json` 的 plugin 列表。

---

遵循最佳实践
保持插件职责单一，避免在同一个插件中混合无关功能。所有可能出错的操作请用 try/catch 包裹，以免插件异常导致整个程序崩溃。将敏感信息（如密钥、 URL）放入 `pluginSettings`，让用户可以在不修改代码的情况下进行配置。尽量在钩子中使用异步操作，并避免在高频钩子中做同步耗时工作，以保持响应速度。

---

解决常见问题
如果插件没有生效，请检查控制台或日志中是否有加载错误信息。确认插件路径正确且可访问，以及返回的钩子对象结构是否符合要求。若多个插件对同一事件进行冲突修改，可尝试调整加载顺序或在插件内部加入优先级判断。遇到权限拒绝或网络超时时，查看插件内部是否正确处理了认证和错误返回。
